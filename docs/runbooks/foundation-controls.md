# Foundation-only controls

The temporary foundation status page is not a migrated legacy window and has no visual parity claim. Its non-legacy identifiers are foundation-preview (development fake-backend banner), foundation-inspect (metadata command button), foundation-info (validated metadata result). All are removed/replaced by the skin-kit launcher when that stage is ready. Its Portuguese error is a developer diagnostic, not an accepted replacement for a legacy message.

ui-check.config.json lists the message dialog checkpoint with explicit pending controls and its missing visual reference. Configuration or a passing subset check never means full legacy coverage. The independent foundation flow tests the temporary page only. Native_info exposes build metadata; API liveness exposes process status, not database readiness. No business workflow, data access or permission is stubbed by these diagnostics.

The DEV-only `/?skin=controls` fixture exercises WdFrame/WdButton/WdEdit using selected generated WIN_Form_Clientes controls. It is a component gallery, not the customer form: Validar counts clicks and Cancelar clears fixture text. Non-legacy identifiers: skin-fixture-A/B, skin-frame-A/B, skin-reopen, skin-disable, skin-clicks, skin-mnemonics, skin-mnemonic-duplicate and synthetic skin-mnemonic-hidden/other/literal buttons. Mnemonic mode overrides Validar with a test caption; the extra buttons exercise hidden/ambiguous/literal-caption defaults, not customer actions. Portuguese chrome accessibility labels are fixture/UI accessibility text, not extracted captions. Two instances prove local callbacks/state without native IPC. Component-region scores live in docs/evidence/visual/skin-components.json; full-window coverage/visual parity remains unclaimed.

The same gallery now includes editable/read-only WdMemo and WdTable from the customer layouts. Table fixture IDs are listed in docs/screens/WIN_Table_Clientes.md. Synthetic stable string IDs exercise selection/reordering/activation; header clicks report the qualified column without inventing sorting semantics. Width/order changes are now controlled and source-gated. Width/order persistence now follows the source configuration flag. Column visibility settings, search, fixed-left scrolling, masks, skinned scrollbars and HFSQL coupling remain pending. Component scores do not close those gaps.

The message fixture exercises awaited result values and concurrent request queuing, with captions/assets explicitly assumed under Q-12. No business mutation occurs. Its non-legacy IDs and pending source features are listed in docs/screens/WINDEVMESSAGEBOX.md. A captured screenshot without a legacy reference is unscored, never a visual pass.

The DEV-only /?skin=workspace launcher exercises WdWorkspace/useWorkspace with independent mounted synthetic instances, not customer forms. Non-legacy IDs: workspace-launcher, workspace, workspace-canvas, workspace-open, workspace-tasks, workspace-window-N (and -frame/-task), workspace-result. Task captions/geometry/focus defaults follow ADR-003. Partial source controls remain a fixture; no full-window score or business parity is claimed. Browser flows cover stacking, title drag, viewport resizing, minimize/restore/close, modal focus and no native child commands. Saved geometry uses ADR-003 defaults; unresolved anchor metadata and native limits/appearance remain pending.

U-SKIN-01: generated anchor labels are available; percentage rates and nested-container resize semantics are not fully decoded. Shared controls use the explicit ADR-003 defaults or supplied per-axis rates. The non-legacy skin-table-resize toggle exercises width/height and bottom anchoring without changing selection. Workspace maximize/restore checks source form button margins and edit widths; these checks do not recover rates or close native resized-window parity.

Manual sizing uses source Resizable/With grip flags through the shared react-rnd WindowInteraction adapter, including real WdModal forms/pickers. Non-legacy workspace-open-fixed/workspace-open-no-grip create capability variants; workspace-window-N-resize (and -resize-n/e/s/w/ne/nw/sw) identify handles. Public parent bounds retain opposite edges for north/west sizing; handles keep their frame's keyboard scope and existing arrow behavior. ADR-003 records geometry/drawing defaults. Native persistence lifetime and limits/appearance remain unverified.

U-SKIN-02: native minimum/maximum dimensions, sizing-border/grip appearance and resize keyboard routing are not captured. Source-base minimums and target handles/keys are explicit ADR-003 defaults; browser resizing does not resolve native acceptance.

U-SKIN-03: source Save position is enabled for the borrowed customer form, but centered-opening precedence, size/state retention, multi-instance save timing and native WebView storage lifetime remain unconfirmed.

# Report inventory

All 28 report units have a mapping note, a report specification, a parity CSV and independent review. The [unit index](README.md) links them. There are 27 report designer images; the combined detailed material-consumption report lacks one.

- Nine master-list reports use embedded SQL that the dossier does not print. Compiler evidence recovers selected items; filter/sort/destination proposals remain assumed.
- Material consumption reports distinguish document exits, repair materials and their union, detailed and summarized outputs, and vehicle-oriented outputs. Query joins, description filters and mechanic sources differ by branch.
- Labor reports group by order, mechanic or vehicle and implement source-specific string/rounding/reset rules. Labor start timestamp filtering is distinct from interval overlap.
- Order/delivery/payment reports use different data sources; some read live UI tables and inherited formatted values. Payment-report title/caption inconsistencies remain facts until a later decision changes them.
- Article statements use historical opening movements and current-period movements with inclusive boundaries; potential boundary overlap is retained as a question.

Report specs separate printed visible extents from hidden designer controls and keep inferred image readings distinct from parsed fields.

All 28 reports now have initial preview/PDF paths through the shared Paged.js HTML/CSS pagination and Chromium adapter ([ADR-005](../decisions/005-reports-integrations.md)). Thin band/control adapters reuse extracted definitions; queries, grouping and calculations remain explicit per family. Preview uses the same paginated HTML as the PDF. `python scripts/report-layouts.py --check` checks the 28 definitions/526 controls against preserved source geometry, local dossier metadata and committed spec captions; it requires the local evidence identified by `analysis-local/latest.json`.

`RPT_Ordens_Reparacao` and `RPT_Materiais` require snapshots of the actual caller table rows/order, effective filters where applicable and inherited formatted values. They do not substitute unrestricted database reads. Other paths retain their named-query, assumed embedded-query, file or explicit order-number inputs. The three report-filter windows preserve their distinct parameters and dispatch branches; implementation does not resolve the remaining source assumptions above.

Completion follow-through reproduced and corrected mixed-format delivery Date and mechanic reception DateTime ordering through real PostgreSQL. Actual 26-family offline PDF checks assert the source company Open assignment, while distinct material joins, description omission, labor sentinel/carry/reset behavior, live-material snapshots and source totals have focused positive tests. A 120-row generic delivery PDF exposed hidden repeated headers: Paged.js 0.4.3 partial margin-map replacement and content:none leaking across margin boxes. Generic layouts now reuse only common band CSS and declare their own source footer plus all four margins, preserving physical repeated headers/page counters without another renderer.

Generated target PDFs and browser previews establish the initial paths, not visual parity. Legacy goldens must still settle pagination/wrapping, empty/NULL behavior, grouping/reset scope, destination inheritance and unresolved designer properties. Native print dialogs/devices, packaged offline font/Chromium availability and Windows/macOS acceptance remain separate gates; parity completion and visual acceptance remain pending.

Native output adapters consume the existing generated PDF bytes without another render. `save_report_pdf` uses an owned rfd save dialog and atomic selected-file replacement; `print_report_pdf` uses PDFKit with no scaling/autorotation on macOS or the registered PDF handler's fixed print verb on Windows. A requested/handoff result never means physical completion; macOS's ambiguous false return is `not_requested`. Non-legacy preview controls are `report-save-pdf`, `report-print-pdf` and `report-output-result`. Browser IPC simulations test caller waiting/cancellation/status only. Native panel/device, Windows handler scaling and host acceptance remain open, with no U-row promotion.

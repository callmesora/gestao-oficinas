# ADR-002 — Lossless values and exact arithmetic

- Date: 2026-10-23
- Status: Accepted (owner may supersede with a new ADR)
- Decided by: default
- Parity rows affected: no status changes during framing; affected units retain their existing IDs.

## Context and evidence
docs/schema/schema-draft.md and docs/data/profile.md record 17 tables/135 items, money-like reals and decimals, sentinel dates, trailing spaces, duplicate labor identifiers and orphan links. docs/legacy-inventory.md records driver-generated binary keys and unused generated IDs.

## Decision
Use decimal strings across JSON and decimal.js for money and quantities; PostgreSQL NUMERIC stores exact values. Keep signed/unsigned large identifiers as decimal strings at all JS boundaries. Preserve legacy date/time text and empty/zero/NULL distinctions until each mapped operation converts explicitly. Calculated durations use an exact integer count transported as a decimal string with an explicit unit tag (centiseconds, milliseconds, seconds or minutes). Each unit map chooses its legacy-evidenced unit before implementation; conversion is explicit and lossless, never an unlabelled JS number. PostgreSQL stores the count as NUMERIC(scale 0) with its unit, while original legacy duration/time fields remain preserved. No blanket trim or rounding. Preserve duplicate original IDs with a separate internal identity and original-value columns; rebuild business indexes from component columns, retaining import provenance. Do not silently remove or repair anomalous records. Import decisions per column must be explicit before schema v1.

## Consequences and verification
Test positive/negative half rounding from evidence, extreme IDs, duration unit conversions/overflow and negative values, null/empty values, accents and spaces. Reconcile counts, keys, quantities and durations; quarantine/report records that cannot be represented without loss. No invented constraints that reject current negative stock or orphans.

Artigos (MIG-7K.1, before translation): source preco is real8 and stock Decimal(size7); masks +999999999,99 /999999999,999 establish presentation/new-entry capacity, not PostgreSQL scale/range or rounding. Return both NUMERIC fields as exact nullable strings; sort qualified typed source columns before text transport (ADR012). No price/stock arithmetic or Number/parseFloat/toFixed is needed in this master-data slice. Save input price accepts nullable raw string shape; after source required/barcode checks, accept finite plain decimal grammar only (optional sign, integer/fraction, dot separator; no exponent/NaN/Infinity), before any write. Invalid transient drafts roll back with existing typed invalid, no invented text; their relation to impossible native numeric entry remains U03. Storage capacity errors retain typed failed/rollback, never silent truncation.

WIN_Data (MIG-7M.1, before translation): raw Return format AAAAMMJJ is an eight-character calendar date, separate from UseSystemMask display. Keep original string/NULL, live display and lifetime accepted-edit flag separate. Cancel always returns the exact original argument; untouched Confirm also preserves it under this explicit target default/U-W16C5A7-05, including empty/zero/opaque anomalous text. Only deliberate valid input produces compactYYYYMMDD; no Date.parse/valueAsDate/timezone or timestamp conversion. The target system-mask default is project pt-PT DD/MM/YYYY; valid zero displays00/00/0000, NULL/empty blank, other opaque values remain visible verbatim. Deliberate blank returns empty string, never NULL; deliberate00/00/0000 returns00000000. Validate other edited dates with Gregorian month/leap/year1..9999 rules, with no autocorrection. Exact native coercion/mask/locale boundaries remain U05; repair datetime conversion belongs to its actual caller.

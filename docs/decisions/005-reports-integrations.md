# ADR-005 — Fixed reports and narrow native adapters

- Date: 2026-10-23
- Status: Accepted (owner may supersede with a new ADR)
- Decided by: default
- Parity rows affected: no status changes during framing; affected units retain their existing IDs.

## Context and evidence
docs/mapping/reports.md records 28 fixed report specs, nine embedded SQL proposals and one missing report image. docs/mapping/jobs-and-integrations.md and docs/evidence-report.md inventory actual platform calls.

## Decision
Use fixed HTML/CSS report layouts with PDF output and a native printing adapter; preserve band breaks, filters and totals. No end-user designer is inferred. Migrate only evidenced devices, INI settings, command-line modes and external programs. Native commands are narrow and scoped; never expose arbitrary SQL/shell/filesystem operations. Use a deliberate CSP and minimum Tauri capabilities. Distribution initially uses a local Windows acceptance installer; signed prod/test update channels need real endpoints/keys later, never an embedded GitHub token.

## Initial report engine (before implementation)

Use Paged.js 0.4.3 ([MIT/version](https://github.com/pagedjs/pagedjs/blob/v0.4.3/package.json)) with the existing Playwright 1.64.1 Chromium [PDF API](https://playwright.dev/docs/api/class-page#page-pdf) (Apache 2.0). A thin adapter maps source millimetre bands/visible controls; Paged.js owns pagination, running headers and page counters. Print the same immutable offline HTML shown in sandboxed preview, with network requests blocked and pinned Noto Sans 5.3.0 Latin fonts embedded (OFL 1.1; retain notices). No custom text-layout engine or end-user designer. pdfmake (MIT) remains a fallback only if this evaluation fails; pdfme (MIT) requires actual positioned-template/designer evidence. Neither is installed.

First consumers are `RPT_Ordens_Reparacao` (explicit live caller rows/filter/order, never unrestricted database substitution) and `RPT_Extrato_artigos` (original joins, UNION ALL, inclusive historical20000101000000→cutoff/current bounds, exact stock1/2 arithmetic and event order). Article breaks are an explicit source-order/header inference. Evaluation defaults are portrait where orientation is unknown, Noto Sans/left alignment where missing, fixed-cell clipping, blank NULL display and retained bound/prior text for unsupported priority/stock; raw values stay intact. U-R09/U-R20 remain open. Packaged/offline Chromium provisioning, native printer adaptation, source golden outputs and Windows/macOS acceptance remain separate gates.

All 28 layouts (526 controls) reuse this adapter with explicit query/event consumers. Nine encoded list queries follow existing `docs/evidence-report.md:138–146` proposals, labelled assumed: retain proposed browse order/public fields and the Viaturas customer join; never expose passwords. Inventory initially traverses its bound artigos file without an invented active-only filter; order remains unresolved. Named parameters retain exact names/explicit NULL condition omission; table reports require live rows. Unknown Resumo body/group settings do not authorize hidden bodies or invented aggregation. Labor reuses actual datetime/duration helpers and sentinel/displayed-time sums. Missing literals stay blank. These are initial development paths, not completed report parity.

## Repair-state color adapter (MIG-7I, before translation)

Source WIN_Form_estados_reparacao.wdw:237–240 passes an integer by reference to SelectColor(scAnyColor), ignores its Boolean result and always copies that integer to preview/input. [PC SOFT](https://doc.pcsoft.fr/fr-FR/?3013045=&name=SelectCouleur) documents OK mutation/cancel; [PixelColor](https://doc.windev.com/en-US/?1000024335=) documents R+256G+65536B. Installed rfd0.17.2 has no color chooser. Use one awaited narrow Tauri command with nullable unsigned32 input and distinct selected/cancelled results; errors reject without new user-facing text. Preserve raw input on cancellation, including NULL/high bits; never mask stored Cor to24bit. Initialize unsupported/null values with picker black only (assumed reversible default); selection returns an ordinary24bit WINDEV color.

Use direct platform APIs rather than a generic shell or bundled C dependency: macOS /usr/bin/osascript with a fixed embedded Standard Additions `choose color` script and validated numeric argv, no caller script/title/path. AppleScript -128 is cancellation, other errors fail;8bit↔16bit uses×257/nearest rounding by default. [Apple chooser](https://developer.apple.com/library/archive/documentation/LanguagesUtilities/Conceptual/MacAutomationScriptingGuide/PromptforaColor.html), [error reference](https://developer.apple.com/library/archive/documentation/AppleScript/Conceptual/AppleScriptLangGuide/reference/ASLR_cmds.html). Windows uses owned ChooseColorW/CHOOSECOLORW on the Tauri UI thread, CC_RGBINIT|CC_ANYCOLOR, local16-color storage; FALSE+CommDlgExtendedError0 cancels, nonzero fails. [Microsoft contract](https://learn.microsoft.com/windows/win32/dlgbox/color-dialog-box). Declare the already locked windows-sys dependency/features directly. No arbitrary process/SQL/filesystem command is exposed. Allow only one color dialog at a time, reject a competing request, and discard detached UI results. Native ownership/focus/app-close behavior, exact special-color handling and WINDEV chooser appearance remain explicit OS/U acceptance gates; browser injection proves only caller continuation.

## Consequences and verification
Each report needs data/text/total checks and visual comparison; printing and scanners require real native/device checks. Browser printing does not prove packaged printing. Missing external resources remain named acceptance dependencies, not stubbed verified features.

Initial callers: nine simple lists invoke their report-owned embedded query; repair orders and materials pass actual visible table rows/order plus effective filter/total. Report-only HTTP body limit32MiB accommodates the imported15,667-row screen snapshot; other routes keep their existing limits. Missing inherited company text stays blank until supplied. Preview/PDF download are development functionality; no browser print button is presented as native printing.

Report preview CSP follow-through (before correction): the scriptless sandboxed srcdoc preview requires self-origin frames and embedded data fonts. Permit frame-src self and font-src self/data while retaining existing script/connect/object/base restrictions; do not enable remote frames, inline report scripts or broad native capabilities. Browser checks apply the desktop policy explicitly; actual WKWebView/WebView2 preview/download/printing remain separate acceptance.

Report date ordering uses the existing ADR002 Date/DateTime comparison projections at source-declared ORDER BY points, preserving raw printed values. Mixed supported text representations must sort by the same calendar value; payment's intentional absence of ordering remains unchanged.

Generic Paged.js bands must emit a complete four-side margin rule and only the report's actual margin boxes. Separate common band styles from initial-template default counters: this installed engine replaces partial margin maps and leaks content:none visibility into later boxes. The120-row physical-PDF regression must retain repeated headers, page counters, all rows and totals after page1; no manual page layout or second engine.

Native startup maps only named modulo=t/m and artigos=1 arguments from source WIN_MENU722–975; expose neither raw argv nor unrelated options. Support PC SOFT's documented `/name=value` and `-name=value` syntax, including spaces around equals; duplicate/unsupported values select no mode as a reversible default until native legacy evidence. EndProgram uses Tauri's app exit request with fixed success code, no caller process/code. Browser termination remains a visible state; native process and both host argument acceptance are separate checks.

Persistent report service provisioning (before implementation): an async configured-renderer factory accepts an explicit absolute local Chromium executable, SHA256 and expected version; validate these before serving reports, using the same pinned Playwright/Paged.js/Noto assets. No normal-launch download, remote fonts, cache guessing or silent fallback to another executable. Absent configuration leaves reports typed unavailable; incomplete/mismatched explicit configuration fails startup without secrets. Provision the runtime separately on the service host (Windows/macOS); desktop clients receive generated HTML/PDF and do not bundle another renderer. The isolated development Chrome path remains explicit development behavior. Record the concise deployment commands in the existing README; offline smoke must use the configured executable.

Native report output (before implementation): consume the exact generated PDF through bounded, strictly validated report-ID/base64/PDF requests; expose no caller path, executable or shell. Save through owned rfd OS dialogs, preserving cancel/failure and replacement confirmation. macOS printing uses PDFKit/NSPrintOperation on the UI thread, preserving PDF page geometry with no target reflow. Windows uses only the registered PDF handler's fixed [ShellExecuteW print verb](https://learn.microsoft.com/en-us/windows/win32/api/shellapi/nf-shellapi-shellexecutew) on an app-created private cache PDF; missing association fails, with no alternate executable. Bound/clean only owned cache files without deleting active jobs. Results distinguish request/handoff from actual printer completion; browser adapters, build and physical-device checks remain separate. Add no reporting engine. Native panel cancellation/error distinctions and Windows handler scaling remain explicit acceptance limits.

Scanner input (before native implementation): WIN_Leitor_cod_barras412–427 selects Postos1 then its configured Terminais, reads to EOT/first empty line, and performs no close/move/delete in this window or its material caller. Preserve read-only, repeatable input. A native-owned local manifest grants each exact terminal code and unchanged database folder/filename one absolute host file plus an explicit utf-8/windows-1252/utf-16le decoder. IPC supplies only that source identity, never a file path or grant. Missing provisioning is unavailable; invalid configuration, malformed bytes, symlinks/reparse points, nonregular/changing/oversized input fail without fallback. The source has no encoding option; [fOpen documentation](https://doc.windev.com/en-US/?3036036=) makes its default project-dependent, so configuration does not establish legacy charset parity. Preserve original paths/data; no arbitrary read/write/shell capability or inferred consumption.

# ADR-003 — Legacy MediaPlayer replica and window behavior

- Date: 2026-10-23
- Status: Accepted (owner may supersede with a new ADR)
- Decided by: default
- Parity rows affected: no status changes during framing; affected units retain their existing IDs.

## Context and evidence
docs/screens/, docs/navigation.md, docs/evidence/images/ and docs/mapping/event-codes.md describe the controls and caller contracts; templates/ui-kit/ supplies the MediaPlayer primitives. Runtime appearance and several actions remain unresolved.

## Decision
Reproduce the Portuguese legacy captions, geometry, masks, tab order, keyboard behavior and MediaPlayer skin. Use generated layouts and exported project assets. Maintain non-modal windows in an in-app desktop workspace with independent window state; modal Open/Close and message boxes use awaited dialog results. Use TanStack Table for reusable table state and React Hook Form with zod for forms, behind legacy primitives. No business behavior derives solely from library defaults. Controls keep exact legacy data-testid values.

Message clipboard default (Q-12; decided by default): route the standard copy event/Control+C to the mapped hidden copy action, retaining its exact title/separator/message payload. Keep that off-canvas control out of tab traversal. The encoded legacy shortcut/tab flags are still U-W36869F-02, so this route is assumed until confirmed. Use the WebView clipboard API for the hidden action; packaged Windows clipboard behavior requires native acceptance.

Caption mnemonic default (decided by default): interpret the first unescaped & in button captions as Alt+letter, && as a literal &, and keep a trailing & literal. Render an underlined letter; the native Windows underline-visibility preference remains unverified. Scope activation to the focused in-app frame/modal, ignore disabled/hidden/inert controls and Ctrl+Alt (AltGr), and leave duplicate eligible letters unhandled rather than choose an unknown winner. These defaults do not recover encoded custom shortcuts or resolve the existing keyboard U items. Explicitly literal captions can opt out.

Workspace defaults (decided by default): center a newly opened instance with a small cascade for subsequent instances; bring the focused/clicked instance forward. Drag its title within the workspace, keep its title reachable, and retain component state while minimized. Task buttons restore minimized instances and the last focused non-chrome control; closing removes only that instance and focuses the top remaining one. Maximize fills the workspace with at least the source base dimensions, restoring prior coordinates afterwards. These are in-app adaptations, not recovered legacy window-manager behavior. Geometry persistence follows the default below; native window-manager acceptance remains separate.

Control anchor-rate default (decided by default): use generated anchor flags and explicit percentage rates when supplied. Where rates are encoded, use 100% for an enabled stretch axis; move 100% on an enabled right/bottom axis only if that axis does not also stretch. This avoids doubling displacement on combined flags and remains assumed, not recovered metadata. Missing/unrecognized anchor flags keep original geometry; resulting dimensions have a zero minimum. Per-control rates override this default; nested-container/rate recovery and native resized comparisons remain U-SKIN-01 in foundation-controls.md. Source base geometry is never overwritten.

Workspace resize default (decided by default): enable manual sizing only when generated Resizable is true. Edges/corners support sizing, including windows without a grip. A generated With grip flag draws the bottom-right grip; its target drawing/keyboard behavior is assumed. North/west sizing preserves the opposite edge and stops at the workspace origin. Drag changes width/height; arrow keys change dimensions by 8 pixels (Shift: 1). Use source base dimensions as the reversible minimum until native minimum-size metadata is confirmed. Maximize retains manual dimensions for restore. Missing flags do not enable sizing; geometry persistence follows the default below. Native limits/drawing/keys remain U-SKIN-02 in foundation-controls.md.

Saved-geometry default (decided by default): when generated Save position is true, remember only normal workspace bounds and the maximized flag per layout name in a versioned local WebView setting (gestao-oficinas:window-geometry:v1:). Restore this before centered opening; cascade additional instances and clamp bounds to reachable workspace dimensions, retaining source-base minimums. Last explicit close wins; on pagehide, save open instances in stack order so the top instance wins per layout. Never reopen minimized or persist control/business data. Ignore stored sizes for non-resizable windows and stored maximize state without a source maximize flag. Invalid/unavailable storage falls back to normal opening without a new error dialog. Per-layout precedence, save timing and native storage lifetime remain assumed under U-SKIN-03 in foundation-controls.md, not a recovered legacy registry/INI key.

Real modal consumers use the same versioned geometry store and source Resizable/With grip/Save position flags. The viewport supplies reachable bounds; default modal centering and maximized 20px viewport inset retain the existing in-app adaptation. Drag the title or size edges/corners without replacing mounted controls; minimize retains inputs and restores the last focused content control. Resize handles stay outside source Tab traversal; a focused handle supports the existing 8px/Shift1px arrow default. Close/pagehide saves normal bounds plus maximize state only, including successful saves and picker cancellation. Nested dialogs own their own keys, geometry and result lifetime. Exact parent-centering/native limits/grip/keys/persistence remain the existing U-SKIN-01..03 and unit U01 gates; no legacy runtime equivalence follows from browser tests.

Table sizing default (decided by default): allow interactive column width changes only for generated Adjustable width=true. Keep source widths until a caller supplies widths or the user resizes. Use qualified column paths for controlled width state; resizing never changes sorting or row selection. Until native sizing edges are captured, use a 24px minimum (or the source width if smaller) and arrow steps of 8px (Shift: 1) for the target resize handle. Handle geometry/keys/minimum remain U-SKIN-04 in foundation-controls.md. Disabling user adjustment does not discard caller-controlled widths. Generated Movable=true also enables header drag reordering; do not cross fixed-left/non-movable columns. Dropping uses the target current index; Ctrl+Shift+Left/Right moves an eligible focused header one position and retains focus. Order is caller-controlled or isolated local state, keyed by qualified paths. These target interaction defaults remain U-SKIN-04. Width/order persistence and search remain separate features.

Saved column-layout default (decided by default): source Saves col. config.=true enables a versioned WebView setting, keyed by owning window and qualified table path (gestao-oficinas:table-layout:v1:). Save only column widths/order after explicit layout changes; never row content/selection, filters or sort. Reconcile stored keys against current visible source columns, keep fixed/non-movable barriers, and append new columns in source order within their movable segment. Invalid/unavailable settings fall back without blocking the UI or overwriting settings on read. The distinct Save on exit flag is not a UI-layout persistence switch. Native timing, visibility configuration and storage lifetime remain U-SKIN-05 in foundation-controls.md.

Edit-control default (decided by default): preserve generated Password and TAB Key flags and positive Text input_size as a user-entry maximum (0 is unlimited). Keep bound/programmatic values intact, including oversized legacy values and string IDs; do not use browser numeric coercion. Automatic erase=true selects the current value on entry, preserving it until the user types; suppress first-click mouse-up caret placement, then allow later clicks/selection. Explicit caller focus handlers run after this default. Native mouse selection details and character-count boundaries remain U-SKIN-06 in foundation-controls.md. Source masks, required/null/zero rules and automatic completion remain separately mapped behavior.

MIG-7C2 numeric entry: explicitly opt in the customer code, vehicle year/month and four terminal position controls to their generated integer masks (10/4/2/2 digits respectively). [PC SOFT InputMask](https://doc.windev.com/en-US/?2510033=) describes 9/space numeric masks and locale-dependent separators; supplied masks/images establish grouping, while exact runtime edit/coercion behavior stays unit U01/U03. Keep ASCII digit drafts as strings, use source space grouping for customer code, and reject invalid whole edits or excess new digits without truncating/rounding or stripping invalid characters. Loaded/programmatic values beyond mask capacity remain intact on focus/blur/unrelated saves; allow unchanged or strictly shorter oversized edits as a reversible default. Mask limits never narrow schema/API ranges or text lookup keys. Blank drafts stay explicit: customer retains existing zero-required conversion, vehicle retains the existing empty-to-zero default, terminal retains ADR-016 empty rejection. Validate vehicle drafts before transport so NaN cannot serialize as nullable data; preserve source required-message order. No new user text. Grouped caret/deletion behavior is an assumed editing default pending native capture. [PC SOFT input suggestions](https://help.windev.com/en-US/?1013145=) apply only to eligible text/key items, so numeric flags do not justify numeric suggestions. Text-key assistance remains a distinct retained designer obligation.

File-assisted text input (decided by default at C2): intersect source Text/key binding with File assisted input=true, explicitly opting in customer/unit/descriptive-state Descricao and terminal Codigo. Offer exact nonempty/non-NULL strings from the real currently loaded list, retaining customer HFilter semantics; remove exact duplicates and candidates exceeding the source user-entry limit. Show case-insensitive prefix matches only after nonempty user input/focus, following ADR-009 comparison. Preserve free text; never mutate a draft until deliberate pointer/keyboard acceptance through the caller's real form setter. A compact suggestion list is an assumed reversible presentation (not recovered inline completion); do not persist choices or invent new captions. Arrow navigation/Enter acceptance/Escape dismissal stay inside that input, retain focus and never validate/close the owner. Readonly/disabled inputs offer no choices; no automatic Tab on full input (source flags=false). Ordering/trigger/presentation/native keys stay unit U01; exact file cursor/shared context stays U02. Numeric and nonkey controls remain ineligible. Terminal suggestions must never call folder preparation, which changes the save buffer.

## Consequences and verification
Skin kit precedes business screens. Every opened window/dialog needs control/caption checks, keyboard flows, image-load checks and recorded visual scores. Human visual acceptance remains pending; no score or browser mock proves native parity. Test multiple windows and cancellation explicitly.

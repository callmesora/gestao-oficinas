# ADR-014 — Continue real workflows with a scheduled designer checkpoint

- Date: 2026-10-25
- Status: Accepted by delegated scheduling default
- Scope: sequencing only; no behavior, feature or parity exclusion

## Evidence

The owner's goal explicitly prioritizes real workflows after the first six usable windows and cleanup, allows documented scheduling of parity gaps and requires continuing independent work. MIG-7C ec9599e is complete. MIG-7A.2a ecc4fe9 delivers header search/configuration. Subsequent actual customer/vehicle browser evidence proves exact large code/memo persistence, known field traversal, maximize/minimize/restore and creation/selection through the real customer picker with refreshed vehicle options and no filter leak. Recovered raw table metadata now has a reproducible source path. Remaining modal geometry, complete numeric mask entry, exact native menus/scrollbar tooltip appearance and runtime shared-context edges do not supply data or APIs required by an independent leaf lookup.

The agent-added ROADMAP gate requiring all three full designer follow-ups before any remaining leaf is broader than the owner's real-workflow priority. Narrow that scheduling gate using the executed consumer evidence; do not mark unfinished parents Done.

## Decision

After the bounded MIG-7A.2b metadata/scroll/tooltips delivery is reviewed, checked and pushed, continue remaining leaf workflows. First: estados_descritivos list/form, whose source map shows two text values, mandatory code, selected-record writes and a description-returning picker. Read its complete evidence before implementation; source selector mode/30px rows/previous-next/actual later caller remain required.

After two additional real leaf workflows, run checkpoint MIG-7C2 before a third. Its concrete scope includes retained customer/vehicle/unit designer follow-ups: modal manual resize/saved geometry, numeric mask entry, exact column/menu/scrollbar tooltip behavior and source/target caller/context audits. Preserve the existing stage-5/6/7 follow-up briefs, U IDs and parity rows. Runtime/native/human-only unknowns may retain their precise MIG-15 assignment; known missing target behavior cannot be called native acceptance or erased. The full parents stay In progress until their actual obligations close. This checkpoint is a scheduled dependency, not an unspecified final polish phase.

All target behavior still requires the original source/ADR evidence, actual tests and sequential reviews. No row is promoted, gate weakened, feature excluded, production action authorized or accepted data/architecture decision changed by this scheduling decision. Full migration/acceptance remains the goal.

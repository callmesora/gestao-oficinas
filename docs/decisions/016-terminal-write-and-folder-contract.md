## Decision

Selected internal string _row_id identifies normal edit/delete. Create serializes exact duplicate checks under table lock; no MAX source identifier is invented. Normal update rejects code changes. One save/delete is one transaction, committed success only; typed rollback/no invented error text follows ADR-008/015. Retain NULL/unchanged strings; new numeric positions default0 from source schema. Validate unsigned byte bounds without inventing start/end-order constraints or a relation guard. Runtime form masks/empty numeric coercion stay U; chosen explicit save conversion accepts digit strings representing 0..255, transports an integer and keeps invalid/empty entry unsaved without new user text. Leading-zero drafts remain strings until that conversion; exact native coercion stays unresolved. MIG-7C2 applies the source 99 live-entry mask without narrowing the byte schema range or truncating loaded values (ADR-003).

Folder preparation is a real read returning explicit current-buffer record. The primary tutorial establishes generic prefix search. Use the first matching prefix under current PostgreSQL comparison, with internal identity tie as a documented default. The dedicated HReadSeek page could not be retrieved (403/cache miss); unmatched/first-greater-key positioning and exact HFSQL collation remain U-CDF1C34F-02. Until captured, do not default to overwriting an unrelated next-greater code. This is the safe destructive-choice exception, not a claim that HReadSeek is an exact lookup. If no record is available, retain prior explicit buffer; no invented empty-buffer deletion/write. A found record replaces save identity/mode before opening the chooser, even if chooser is cancelled. Controls remain unchanged except assigned folder. Because initial new-form code stays editable, explicit after-folder-seek save permits changing the positioned record code and rechecks exact duplicates excluding that record. This preserves the source hazard; do not silently turn it into a new insert or block known existing-record repositioning. No test pins locale/tie/no-record unknowns.

Use a narrow native select_terminal_folder command, fixed source title and one initial directory argument; no file reads/writes, shell execution, broad file API or server-side folder selection. rfd async picker returns selected path, cancellation maps to empty string (source API). Reject NUL/oversized initial values at native boundary. Browser development cannot expose an absolute OS folder path; it reports native-only diagnostic, never substitutes a fake selected path. Real Tauri development must exercise this actual UI/API/DB/native command, including cancellation/context and save. A checked isolated Tauri dev config may point to the already running real loopback workflow server; production navigation remains MIG-12 and native packaging/install gates remain separate.

Image-backed Portuguese caption corrections are screen-specific inferred presentation as ADR-015; generated metadata remains immutable. Column search/config/scroll defaults reuse ADR-012/013 where exact raw options prove them. Destructive unresolved default remains safe cancellation ADR-006. No UMC exclusion. Full native/runtime/caller/parity gates remain required; C2 follows this leaf before a third.

## Actual Postos consumer (MIG-7G)

WIN_Form_postos.wdw:467–471 tests **Terminais.NewRecord**, once before FileToScreen (475–477), rather than postos.NewRecord. Preserve that cross-file dependency explicitly. A client-owned TerminalFileContext is shared by actual terminal windows/pickers and Postos; it stores only unknown/new/positioned identity, never credentials, drafts or server-global buffers. Snapshot code editability in the Postos form-opening descriptor; subsequent picker/reset operations cannot retoggle that open form. [PC SOFT HSave](https://doc.windev.com/en-us/?1000021375=&product=WD) confirms HReset establishes NewRecord=True. Reset before terminal Novo, retain it on cancel; found folder preparation positions before the chooser. Successful explicit edit/selector/save establishes target-existing as a documented translation default. Ordinary table fill/row selection/header seek do not invent proven NewRecord effects; initial/failed/deleted-empty/shared native outcomes remain U-CDF1C34F-02/U-CD4F0FE3-02. Unknown state conservatively keeps code readonly until an actual terminal reset establishes new; this safe fallback is assumed, not recovered startup behavior. No query-param or mock context injection.

Postos uses existing schema/internal selected row identity: Codigo nullable unsigned byte (API0..255, required>0, live mask99 without truncating loaded100..255), Descricao nullable text50 required exact nonempty, optional terminal nullable text3, hidden teste nullable text50. Never auto-allocate Codigo or require terminal existence. The actual awaited terminal picker assigns Codigo/origin. Update may change Codigo when the captured context permits entry; API updates selected id and rechecks numeric duplicates excluding itself under a postos table lock. Preserve hidden teste on update, initialize source empty default on create. One save/delete is one transaction; rollback/typed failure/no invented text follows ADR-008/015 rather than ambiguous unchecked fallthrough. Numeric empty→0 is an explicit reversible entry default; required-message order remains code then description. No relationship-delete guard, report, selector or editable table row is invented. New refresh only on true; edit refresh before opening and after any result. Native row-buffer/new-line reachability, UMC and exact U01/02/03 remain open. JPG-backed Descrição presentation follows the existing scoped override pattern.

Asynchronous target reads belong to their actual window lifetime: a closed terminal selector/list cannot later open an edit form or position shared context from its detached modify read. Discard that read on owner unmount; this cancellation safeguard does not undo committed saves/deletes. It is target ownership behavior, not recovered WINDEV asynchronous interaction evidence.

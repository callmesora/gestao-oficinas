# ADR-013 — Preserve named table designer options

- Date: 2026-10-25
- Status: Accepted by delegated default
- Rows: RULE-CC16AB27-028; no status promotion

C2 extends the same explicit opt-in to source-proven vehicle/unit tables (RULE-C039C545-025/RULE-CCB16084-014), retaining the existing descriptive-state/terminal consumers. Their generated raw options name Search magnifiers, Automatic horizontal/Always visible vertical scrolling, truncated tooltips, pixel scrolling and column context menu. All unit/vehicle native U01 appearance/timing/menu obligations remain; no generic export/filter is inferred or broad designer row promoted.

Audit every named option when enabling a real consumer. Explicit Touch scrolling=No disables content swipe panning with touch-action:none; absent metadata retains existing behavior. Mouse/wheel, scrollbar and per-pixel scrolling remain available. Source row height is recorded without margin; use that content height plus the 1px row border observed in the designer images (18→19px), retaining explicit runtime rowHeight overrides such as the descriptive-state selector30. This border interpretation is inferred under the existing visual U01, not recovered native DPI metadata. Verify touch intent with actual Chromium touch events and a positive panning control, not only a CSS declaration.

The raw dossier for TABLE_Clientes explicitly supplies scrollbar, tooltip, magnifier, scrolling, selection and remember-sort/filter options omitted from the generated layout. Preserve exact named values in an optional `table_options` object generated by screen_layout.py. Missing values remain absent; never imply false or overwrite source geometry. Additive metadata on other tables does not establish their implementation parity.

The first customer consumer uses source Always visible/Automatic scrollbar modes and truncated-text tooltips, without changing row data, filters or selection. Retain per-pixel browser scrolling. Tooltip text uses the actual displayed cell value only when it overflows; browser/native tooltip timing and scrollbar skin remain U-CC16AB27-01 until actual platform comparison. Column context menu Yes enables right-click access to the existing ADR-012 column configuration panel; its exact native menu composition remains U-CC16AB27-01, and generic filter/export commands are not inferred from this flag. No invented tooltip message, numeric normalization or persisted business data. Other raw options remain explicit owning-slice obligations until implemented and tested.

Verify exact source-to-generated values, absence when no evidence exists, actual real customer table overflow/tooltip behavior, all existing browser/golden checks and native metadata separately. Generated layouts and manifest are regenerated, never edited by hand.

Chromium overlay auto-hiding must not defeat the source always-visible mode. The opted-in customer table uses a 16px scrollbar track (width/tones inferred from the committed designer image under ADR-003), with native skin/DPI/timing still U-CC16AB27-01. Verify reserved scrollbar width even with an empty actual result, not only a CSS overflow declaration.

Installed Playwright's headless Chromium launcher explicitly adds --hide-scrollbars. UI checks omit that one default argument so source-required scrollbars can actually be measured/captured, as in the normal desktop runtime. All assertions, visual floors/tolerances and native acceptance scope stay unchanged. This is test realism, not permission to hide a parity gap.

Reserve the configuration affordance's header width so it cannot intercept the last column's magnifier after a real scrollbar consumes its gutter. This internal header spacing is an assumed target drawing detail under U-CC16AB27-01; the last-column actual seek must remain usable and tested. Exact native header/scrollbar corner composition stays at MIG-7C2/MIG-15, not verified by a CSS score.

Artigos review follow-through (before correction): source49px last Inativo column exposes caption text painting through the reserved magnifier area. Contain searchable caption overflow inside its existing button without changing source widths, wrapping or magnifier/configuration hit areas. Preserve the full source caption as its accessible name; when source truncated_tooltip=Yes and the caption actually overflows, reuse the displayed-caption hover title behavior already used by cells. This is a narrow reversible target drawing/default under U01, not recovered native tooltip timing/ellipsis behavior. Actual Artigos checks must prove positive text overflow, effective clipping, separate hit boxes, full name/hover title and real last-column seek retaining rows. Existing broader/native acceptance remains unchanged.
